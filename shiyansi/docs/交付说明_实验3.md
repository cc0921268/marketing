## 五、几个关键设计（答辩可能会问）

**Q：为什么 C6 价格异常要截断而不是删除？**
删掉会引入系统偏差——错价可能集中在高价型号（更贵的耳机更容易手工录错），删行等于系统性剔除高端样本，价格分布会左偏。用 winsorize 截断到 `min(品牌上限, IQR上须×3)`，行保留、分布不失真。

**Q：为什么 C8 无效评论只打标不删？**
删掉后就无法证明我们识别过它们，审计链断裂。保留 + 打 `is_valid_review=0`，下游可自行决定要不要用。

**Q：C7 缺失为什么分三级？**
`review_text`/`brand` 缺 → 删行（核心分析对象，缺了没意义）；`price`/`rating` 缺 → 留空（保留行，统计时 skipna，不污染方差）；`interaction_count` 缺 → 填 0（有业务依据：没互动就是 0，不是"未知"）。**填 0 是有依据的补全，填均值是伪造数据。**

**Q：N6 和 N7 怎么保证不混淆？**
两阶段注入：先造 `300-9-9=282` 条干净底料 → 追加 9 条 N7（复制底料行、沿用原 ID、强制改 rating）→ 再追加 9 条 N6（整行复制）→ shuffle → 截断到 300。保证"整行重复"和"ID重复但内容不同"是两类可分别验证的样本。

## 六、6 个 Debug 复盘（文档 §6.2 有详细版）

1. **C5 把空价格记为解析失败（20 条误报）** — `str(None)` 得到 `"None"`，`if not s` 守卫失效。加 `raw_is_blank` 前置判定。
2. **C9 把中文全角逗号转成半角，破坏 249 条评论** — 用 `range(0xFF01, 0xFF5F)` 做全角映射，该区间含全角标点。收窄为只转 `０-９/Ａ-Ｚ/ａ-ｚ`。**最严重的一个坑。**
3. **繁体字一个都没注入** — `_traditionalize()` 遍历方向写反（把简体当 key）。
4. **C3 ID 去重恒为 0 条** — N6/N7 同轮交替掷骰，N7 被 N6 整行复制覆盖。改两阶段注入。
5. **张冠李戴只命中 1 条** — 取差集时可能取到同品牌其他型号，不算张冠李戴。
6. **原始数据变成 318 条** — 两阶段注入没扣减底料名额。

## 七、已知限制（写进报告里更显严谨）

- 数据是**合成的**，评论由模板拼接，语言多样性低于真实评论
- 品牌/型号名真实、评论虚构，**容易被误读为真实口碑**
- 公开切片仅 60 条且**不参与统计口径**，只验证字段映射跑得通
- 无时间序列深度、无用户维度
- `TRAD_TO_SIMPLE` 只收录 45 组高频词条，非完整繁简表
