## 1. 数据来源说明

### 1.1 通道 A：程序合成数据（主数据集，300 条）

| 项 | 说明 |
| --- | --- |
| 生成脚本 | `src/generate_raw_data.py` |
| 生成机制 | 固定随机种子 `seed=42`；从 6 品牌 × 23 型号的产品池中抽样，价格按品牌价格带随机生成，评分按产品口碑基线浮动，评论正文由**模板 + 随机槽位**拼接 |
| 是否为真实数据 | **否，全部为合成数据** |
| 真实性边界 | 品牌名、型号名、价格带参考公开市售信息（**仅用于让数据"看起来合理"**）；评论正文**不是任何真实用户的发言**，是模板拼装 |
| 是否可反推真人 | **不可** — 生成过程不涉及任何真实用户输入 |
| 许可 | 项目自有，随仓库以课程作业形式提交 |

**生成器的"人味"设计**：为避免模板数据过于规整导致清洗规则形同虚设，生成器对同一型号维护了多组评价维度槽位（降噪、续航、佩戴、连接稳定性、通话、做工、性价比），并允许正负评价混排——因此数据中会出现"降噪很好但续航拉胯"这类矛盾表述。这**是刻意的**，用于检验后续洞察引擎能否处理"多维评分不一致"的真实场景。

### 1.2 通道 B：公开数据集切片（可选，默认 60 条）

| 项 | 说明 |
| --- | --- |
| 数据集 | `gyoungjr/amazon-electronics-reviews`（HuggingFace） |
| 原始来源 | Amazon Electronics 评论的公开研究用抽样 |
| 访问方式 | `https://datasets-server.huggingface.co/rows` **只读 API**，无需认证 |
| 许可证说明 | 以 HuggingFace 数据集页面标注为准；本项目**仅用于课程教学，不再分发**，只保留 **≤200 字** 的文本片段 |
| 字段映射 | `text → review_text`（截断）；`labels(0/1/2) → rating(3.0/4.0/5.0)`；`brand/product` **统一标注为"公开数据集/电子产品评论"，不编造**；`price/date/interaction_count` **数据集本身缺失，一律留空交 C7 处理，绝不填充猜测值** |
| 留档文件 | `data/raw/public_slice.csv` + `data/raw/public_slice.meta.json`（含 dataset_id、URL、license_note、compliance 清单） |
| 降级策略 | 网络不可达时脚本 `return 1` 并提示，**主流程不中断**（合成数据通道独立可用） |

> **关键设计原则**：公开切片**只用于验证字段映射适配器可用**，不参与本期清洗统计口径。所有清洗数字（300→282、97.82%）均基于通道 A 的合成数据。这样做的原因是：用两个来源混合统计会让"完整率"失去解释力——公开切片本身 price/date 全空，混进来只会把完整率拉低到无意义的水平。

### 1.3 明确不做的事

| 不做 | 原因 |
| --- | --- |
| 不爬取电商平台真实评论 | 违反平台 ToS；robots.txt 限制；需登录态 |
| 不使用真实用户昵称/头像/ID | 无必要，且构成 PII 采集 |
| 不使用第三方"数据集市场"的付费数据 | 许可链不清晰，无法合规声明 |
| 不伪造"真实来源"话术 | 合成数据必须标注为合成，这是底线 |

## 3. 风险登记表

| 风险 | 等级 | 影响 | 缓解措施 | 责任人 |
| --- | --- | --- | --- | --- |
| 读者误把合成数据当真实市场数据引用 | **中** | 得出错误商业结论 | 4 处文档声明 + 文件名保留 `raw` 语义 + 结论模板强制带"本数据为模拟"前缀 | 全组 |
| 公开切片许可条款后续变更 | 低 | 合规声明失效 | `meta.json` 记录抓取时间与当时页面标注；`--offline-check` 可复核可达性 | 数据负责人 |
| 合成评论中的负面表述被断章取义 | 低 | 品牌声誉误伤 | 本表 §5 显式免责；负面评论示例在文档中标注"合成示例" | 文档负责人 |
| 清洗规则过拟合本数据集 | 中 | 换数据集后规则失效 | 88 项测试覆盖单规则边界（含中文标点保留、NaN 不入 C5、浮点舍入）；规则参数集中在文件头部常量区 | 清洗负责人 |
| 全角转换误伤中文标点 | **曾发生** | 249 条可读评论被破坏 | 已修复：只映射 `０-９/Ａ-Ｚ/ａ-ｚ`；新增 `test_c9_chinese_punctuation_preserved` 回归测试 | 清洗负责人 |

## 4. 敏感信息扫描结果

对 `data/raw/raw_data.csv` 与 `data/processed/clean_data.csv` 做正则扫描：

| 扫描项 | 正则模式 | 命中数 |
| --- | --- | --- |
| 手机号 | `1[3-9]\d{9}` | **0** |
| 身份证号 | `\d{17}[\dXx]` | **0** |
| 邮箱 | `[\w.+-]+@[\w-]+\.[\w.]+` | **0** |
| 银行卡号 | `\d{16,19}` | **0** |
| 微信/QQ 引流 | `加我微信\|私聊\|加V\|QQ群` | 仅出现在**刻意注入的 N8 广告噪音**（如 `加我微信xxx`），已由 C8 打 `is_valid_review=0`，非真实联系方式（为占位符） |

> 该扫描可由评审自行复跑：见 `docs/experiment03.md` §7.3「证据追溯」中的一行命令。

## 5. 声明

1. 本项目数据为**课程作业用途的模拟数据**，不代表任何真实品牌的市场表现、产品质量或消费者态度。
2. 公开数据集切片仅用于**验证字段映射适配器的工程可行性**，不参与本期统计口径，不再分发。
3. 本项目不含任何可识别到自然人的信息；`review_id` 为程序生成的序号，与真实用户无映射。
4. 清洗管线的所有处理均可通过 `data/processed/cleaning_log.csv` 逐条回溯，原始文件全程只读。
5. 若后续实验需要引入真实数据，将在使用前重新填写本表并取得相应授权。
