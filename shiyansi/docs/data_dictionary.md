> **品类说明**：本课程最终选题为**蓝牙耳机（TWS 真无线 + 头戴式）**。实验1 的 15 条样例数据为通用营销字段演示（保留原样不改，以体现 v0.1 的通用性），自实验3 起全部业务数据统一为蓝牙耳机品类，后续实验4—8 沿用同一数据底座。

## 2. 字段字典

### 2.1 原始数据字段（`data/raw/raw_data.csv`，8 列）

| 字段 | 类型 | 允许值/范围 | 说明 | 生成器注入的噪声 |
| --- | --- | --- | --- | --- |
| `review_id` | 文本 | `R0001`—`R0300` | 评论唯一标识 | **N7** 约 3% ID 重复（同 ID 不同评分/互动量，模拟二次编辑） |
| `brand` | 文本 | 6 品牌 × 多别名 | 品牌名（**未归一**） | **N1** 别名混用：`EDIFIER`/`edifier`、`華為`、`新力`、`欧珀`、`redmi`、`Apple AirPods` 等 |
| `product` | 文本 | 见第 5 节产品表（23 型号） | 产品型号 | **N10** 约 4.5% 张冠李戴（品牌与型号不匹配） |
| `price` | 文本 | `￥xx.xx` / `xx.x元` / `1,xxx` / `xx,xx` | 单价（元） | **N2** 货币符号/千分位/欧式小数；**N3** 约 2% 放大 10 倍；**N5** 约 4% 缺失 |
| `rating` | 文本/数值 | 1.0—5.0；**异常时出现 7.5—10.0** | 平台评分 | **N5** 约 8% 缺失；**N10** 约 2% 用 10 分制（需 ÷2） |
| `review_text` | 文本 | 自由文本 | 评论原文 | **N5** 缺失；**N8** 约 5% 无效（纯符号/纯数字/广告/无关）；**N9** 繁体混用 + emoji |
| `date` | 文本 | **5 种格式** | 评论日期 | **N4** `2024-06-01` / `2024/6/1` / `20240601` / `2024年6月1日` / `6/1`（缺年份）；**N10** 约 1% 未来日期 |
| `interaction_count` | 整数 | 0—520 | 点赞+评论互动量 | **N5** 约 6% 缺失 |

### 2.2 清洗后字段（`data/processed/clean_data.csv`，**10 列**）

| 字段 | 类型 | 允许值 | 来源/处理 |
| --- | --- | --- | --- |
| `review_id` | 文本 | 唯一 | **C3** ID 去重后（内容不同保留首条） |
| `brand` | 文本 | 6 个规范品牌名之一 | **C1** 别名归一化后 |
| `product` | 文本 | 23 型号之一 | 原值保留（不一致由 `is_consistent` 标注） |
| `price` | 浮点/空 | >0，≤ 品牌上限 | **C5** 解析 + **C6** winsorize 截断；解析失败/缺失保留为空 |
| `rating` | 浮点/空 | 1.0—5.0 | **C10** 10 分制 ÷2 折算；缺失保留为空（均值 `skipna`） |
| `review_text` | 文本 | 自由文本 | **C9** 繁简/emoji/全角字母数字归一（**中文标点保留**） |
| `date` | 文本 | `YYYY-MM-DD` | **C4** 归一化；缺年份按 2024 补齐；未来日期置空 |
| `interaction_count` | 整数 | ≥0 | **C7** 缺失填 0（无互动即 0） |
| `is_valid_review` | 0/1 | 1=有效，0=噪音 | **C8** 标注（纯符号/纯数字/广告/无关），**只打标不删除** |
| `is_consistent` | 0/1 | 1=品牌型号匹配 | **C10** 标注（张冠李戴），**只打标不删除**，供人工复核 |

### 2.3 清洗日志字段（`data/processed/cleaning_log.csv`，731 行）

| 字段 | 说明 |
| --- | --- |
| `review_id` | 被处理行（可回溯源数据） |
| `action` | 规则代号，如 `C1_brand_alias` / `C6_price_clip` / `C10_inconsistent` |
| `detail` | 人类可读的处理说明（含判定依据） |
| `before` | 处理前的值 |

> **可追溯性设计**：日志逐行记录 `before → after`，任意一条清洗结果都能反查到原始值与触发规则，满足课程"证据链可追溯"要求。

## 3. 10 类噪声清单（N1—N10）

| 编号 | 噪声类型 | 注入比例 | 具体表现 | 对应清洗规则 |
| --- | --- | --- | --- | --- |
| **N1** | 品牌别名 | ~80% 行 | `EDIFIER`、`華為`、`新力`、`欧珀`、`redmi`、`Apple AirPods`、`华为耳机` | C1 |
| **N2** | 价格脏格式 | ~65% 行 | `￥599.00`、`599元`、`1,299.00`、`€599` | C5 |
| **N3** | 价格 ×10 | 2% | 真实 599 → 记成 5990 | C6（截断） |
| **N4** | 日期多格式 | ~60% 行 | 5 种写法混用，含缺年份 `6/1` | C4 |
| **N5** | 字段缺失 | price 4% / rating 8% / interaction 6% / text 2% | 空串或 `NaN` | C7 |
| **N6** | 整行完全重复 | 3%（9 行） | 所有字段逐字节相同 | C2 |
| **N7** | ID 重复 | 3%（9 行） | 同 `review_id`，rating/interaction 不同 | C3 |
| **N8** | 无效评论 | ~5%（15 条） | `。。。。。`、`666666`、`加我微信xxx`、`天气不错` | C8 |
| **N9** | 繁简 / emoji 混用 | ~12% | `續航`、`藍牙連接不穩`、😂👍、全角 `５９９` | C9 |
| **N10** | 逻辑矛盾 | rating 2% / 未来日期 1% / 张冠李戴 4.5% | 8.7 分、2024-12-31、华为品牌配 Redmi 型号 | C10 |

> **两阶段注入设计**：N6（整行重复）与 N7（ID 重复）如果在同一轮循环里交替掷骰，N7 行会被 N6 的整行复制覆盖，导致 C3 恒为 0 条。因此生成器改为**先造 `n_base = n - n_dup_id - n_dup_full` 条干净底料 → 追加 N7（复制底料行、沿用原 ID、改 rating/interaction）→ 再追加 N6（整行复制）→ 全局 shuffle → 截断到 n 条**。这保证了 C2 与 C3 是**互斥**的两类，可分别验证。

| 编号 | 规则 | 处理方式 | 理由 | 本期命中 |

| **C1** | 品牌别名归一 | 查表映射到 6 个规范名 | 同一品牌多写法会分裂统计口径 | 243 条 |
| **C2** | 整行重复 | 完全重复剔 1 条（`keep=first`） | 平台二次提交常见 | 9 行 |

### 7.1 两条踩过的坑（已修，留档供复盘）

**坑一：C5 把空价格也记为"解析失败"（20 条误报）**
`str(None)` 得到 `"None"` 而非空串，`if not s` 判断失效。修复：先判 `raw_is_blank`（`None` / `NaN` / 全空白），缺失归 C7 管，C5 只处理"有值但格式脏"。

**坑二：C9 把中文全角逗号转成半角，破坏 249 条可读评论**
最初用 `range(0xFF01, 0xFF5F)` 做全角→半角映射，但这个码位区间**包含全角标点**（`，。！？：；`）。修复：收窄为仅 `０-９` / `Ａ-Ｚ` / `ａ-ｚ` 三组显式映射。C9 命中数从 249 降到 36（真实需要修的只有繁简、emoji、全角数字）。
